# Руководство по настройке базы данных EduCenter CMS

## Текущее состояние системы

Система EduCenter CMS в текущей версии использует **localStorage** браузера для хранения данных. Это означает, что все данные (курсы, страницы) сохраняются в вашем браузере и не видны другим пользователям. Данные привязаны к конкретному браузеру и устройству.

## Архитектура с базой данных

Мы подготовили полноценную архитектуру с использованием базы данных. Система поддерживает два режима работы:

**SQLite (для разработки):** Лёгкая встроенная база данных, не требует установки сервера. Данные хранятся в файле `educms.db`. Идеально подходит для разработки и тестирования.

**MySQL (для production):** Полноценная система управления базами данных. Требует установки и настройки MySQL сервера. Рекомендуется для рабочего сайта с реальными пользователями.

## Установка и запуск

### Шаг 1: Установка зависимостей

Для работы с базой данных необходимо установить Python и зависимости:

```bash
cd /workspace/educms/backend
pip install -r requirements.txt
```

Для использования MySQL дополнительно установите драйвер:

```bash
pip install pymysql
```

### Шаг 2: Настройка подключения к базе данных

Откройте файл `database.py` и измените настройки подключения. Для использования SQLite ничего менять не нужно — система работает сразу. Для переключения на MySQL измените конфигурацию:

```python
DB_CONFIG = {
    'driver': 'mysql',  # Измените с 'sqlite' на 'mysql'
    'database': 'educms',
    'host': 'localhost',
    'user': 'root',
    'password': 'ваш_пароль',
}
```

### Шаг 3: Запуск сервера

```bash
python api/app.py
```

Сервер запустится на порту 5000 и будет доступен по адресу `http://localhost:5000`.

API будет доступен по следующим адресам:

- `GET /api/courses` — получить все курсы
- `GET /api/courses/<id>` — получить курс по ID
- `POST /api/courses` — создать курс
- `PUT /api/courses/<id>` — обновить курс
- `DELETE /api/courses/<id>` — удалить курс

Аналогичные endpoints существуют для страниц `/api/pages`.

## Миграция существующих данных

Если у вас уже есть данные в localStorage, их можно перенести в базу данных. Для этого:

1. Откройте страницу админ-панели в браузере со старыми данными
2. Выполните в консоли браузера следующий код:

```javascript
const courses = JSON.parse(localStorage.getItem('educms_courses') || '[]');
const pages = JSON.parse(localStorage.getItem('educms_pages') || '[]');
console.log('Courses:', JSON.stringify(courses, null, 2));
console.log('Pages:', JSON.stringify(pages, null, 2));
```

3. Сохраните полученные данные в файл `data.json`
4. Запустите миграцию:

```bash
python migrate.py data.json
```

## Подключение frontend к API

Для подключения frontend к серверу базы данных используйте файл `store-api.js`. Этот модуль заменяет работу с localStorage на API вызовы к серверу.

Все страницы уже настроены на использование API. При запущенном сервере данные будут автоматически загружаться из базы данных.

## Переход в production

Для запуска в production режиме рекомендуется:

1. Используйте MySQL вместо SQLite для надёжности и производительности
2. Настройте веб-сервер (nginx) для проксирования запросов к API
3. Используйте WSGI сервер (gunicorn) для запуска Flask приложения:

```bash
pip install gunicorn
gunicorn -w 4 -b 0.0.0.0:5000 app:app
```

4. Настройте автоматический запуск сервера при перезагрузке системы

## Частые вопросы

**Нужно ли удалять старый код с localStorage?**

Нет, код остаётся совместимым. При отсутствии подключения к API система автоматически использует localStorage как резервный вариант.

**Можно ли использовать другие базы данных?**

Да, архитектура позволяет легко добавить поддержку PostgreSQL или других СУБД. Для этого нужно изменить функцию `get_connection()` в файле `database.py`.

**Как часто создаётся резервная копия?**

Для SQLite регулярно копируйте файл `educms.db`. Для MySQL настройте автоматическое резервное копирование средствами СУБД или используйте внешние сервисы.
